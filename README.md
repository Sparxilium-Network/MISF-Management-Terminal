# MISF Management Terminal

> 最後修改：2026-11-08 ｜ 基於 commit：`ee69d1b`

[GitHub 儲存庫](https://github.com/Sparxilium-Network/MISF-Management-Terminal)

> [!WARNING]
> **本專案仍處於開發階段，請勿用於正式環境。**
> 相關安全保護機制尚未完善。
>
> 目前只有 **APT**（Debian／Ubuntu）在真實主機上測試過；DNF、YUM、pkg 等其他功能不保證可用或安全。

MISF 是一個桌面程式，用來集中管理多台 Linux／BSD 伺服器的套件更新：透過 SSH 連上主機，檢查有哪些套件可以更新，並在你確認後升級。不需要安裝 Java、瀏覽器或另外架設管理伺服器。

- [使用指南](docs/user-guide.md)：批次作業、整理主機清單、設定與解鎖金鑰管理等進階用法。
- [開發說明](docs/PROJECT-DEV.md)：給開發者的建置、架構與測試文件入口。

## 下載與啟動

到 GitHub 的 [Releases](https://github.com/Sparxilium-Network/MISF-Management-Terminal/releases) 下載對應的壓縮檔：

- **Windows**：`MISF-Management-Terminal-windows-x86_64.zip`，解壓後執行 `misf.exe`。
- **Linux**：`MISF-Management-Terminal-linux-x86_64.tar.gz`，解壓後執行 `./misf`。需要圖形桌面環境。

目前只有預先發行版（Pre-release）。不需要安裝，解壓即可使用。

## 開始使用

1. 第一次啟動時先設定解鎖密碼，建立加密主機庫（見下方「保護你的主機資料」）。
2. 按左側的 **「+ 新增主機」**，填入名稱、位址、連接埠與帳號。
3. 選擇登入方式：密碼、匯入私鑰檔（Ed25519 或 ECDSA，不支援 RSA），或使用「SSH 金鑰管理」中已儲存的金鑰。一般帳號可另填 sudo 密碼；留空時會沿用 SSH 密碼。
4. 第一次連線前，按 **「主機指紋」** 核對伺服器指紋並確認。之後指紋若改變，程式會直接阻擋連線，以防連到假冒的主機。
5. 按 **「測試連線」**，程式會自動辨識作業系統與套件管理器，例如「Ubuntu 26.04 · APT」。這次連線用的加密方式、主機金鑰與登入方式會記在主機下方的 **「連線資訊」** 分頁，失敗時也會保留失敗前取得的資訊。
6. 按 **「偵測並檢查更新」** 取得可更新的套件清單。檢查不會安裝任何東西。
7. 確認清單後按 **「進階操作」** 選 **「套件升級…」**，勾選了解風險後執行。結果會列出已升級的套件與仍待更新的套件。

滑鼠停在會連線或使用 sudo 的按鈕上約 1.5 秒，會顯示實際要執行的命令與風險說明。

> [!CAUTION]
> 升級會直接修改遠端系統，無法自動復原；更新核心後需自行重新開機。建議先在一台測試主機上試，也避免同一叢集的所有節點同時升級。

### 支援的系統

| 系統 | 套件管理器 | 支援程度 | 實機測試 |
| --- | --- | --- | --- |
| Debian、Ubuntu | APT | 檢查與升級 | 已測試 |
| Fedora、RHEL 8 以上 | DNF | 檢查與升級 | 未測試，不保證可用或安全 |
| CentOS 7 等 | YUM | 檢查與升級 | 未測試，不保證可用或安全 |
| FreeBSD、DragonFly | pkg | 檢查與升級 | 未測試，不保證可用或安全 |
| OpenBSD、NetBSD | — | 只支援連線測試 | 未測試 |

程式會自動偵測套件管理器；若同一台主機裝了多種（例如同時有 DNF 與 YUM），可在「編輯主機」手動指定。

要一次檢查或升級多台主機、用分類整理主機清單，或調整外觀與預設解鎖方式，請見 [使用指南](docs/user-guide.md)。

## 保護你的主機資料：LUKSbox 加密

主機的位址、帳號、密碼與私鑰**一律加密**存在 LUKSbox 主機庫，不提供未加密模式。

1. 第一次啟動時，程式會先要求建立加密主機庫，建立前無法新增或檢視任何主機。
2. 解鎖密碼至少 8 個字元，且要包含數字、字母、符號其中至少兩種（例如 `abcd1234`，不一定要有符號）。空白只算長度，不算任何一種。之後新增的備援密碼也套用相同規則；既有的密碼仍可照常解鎖。
3. 若資料夾裡有舊版留下的未加密 `hosts.db`（或更早的 `hosts.json`），其中的主機會一併轉入加密主機庫。驗證可以解鎖後，程式會詢問是否刪除原本的明文檔案。
4. 之後每次啟動都要先解鎖；按「鎖定」可隨時鎖上，也可在「設定 > 偏好設定 > 自動鎖定」設定閒置幾分鐘後自動鎖定。
5. 建議新增一組備援密碼或 Passkey，並匯出加密備份，步驟見 [使用指南](docs/user-guide.md#解鎖金鑰與備份)。

> [!IMPORTANT]
> 遺失所有密碼與 Passkey 就**無法復原**資料。請保留一組可取回的備援密碼。撤銷金鑰或更改金鑰後，請重新匯出備份；舊備份仍可用舊金鑰開啟。

加密只保護「尚未解鎖」的檔案，無法保護已遭入侵的電腦。

## 資料存放位置

所有資料都放在使用者目錄下的 `.misf-management` 資料夾，完整路徑顯示在主視窗右上角。

- 主機庫：`hosts.lbx`（LUKSbox 加密）。舊版的未加密 `hosts.db` 只會在建立加密主機庫時讀取一次並轉入，之後不再使用。
- 偏好設定：`ui-settings.json`。只存語言、外觀、視窗大小等，不含任何帳密，即使主機庫加密也不會被加密。
- 操作紀錄：`logs/`。記錄你做了哪些操作及結果，只含主機的顯示名稱，不含 IP、帳號、密碼或遠端輸出。紀錄不會自動清理。請勿在主機名稱中填入敏感資訊。
